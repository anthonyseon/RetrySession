# RetrySession 을 고칠 때

이 저장소는 **감시 장치**다. 틀리면 사람이 "괜찮다"고 믿는 동안 일이 멈춰 있다.
아래는 취향이 아니라 **이 저장소를 만들며 실제로 밟은 함정**들이다. 순서대로 하라.

불변 규칙 자체는 [`CLAUDE.md`](../../../CLAUDE.md) 에 있다. 여기는 **절차**다.

## 0. 고치기 전에 — 무엇을 건드리는지 확인

| 건드리는 것 | 반드시 함께 볼 것 |
|---|---|
| `src/lib/guard.mjs` · 판정 로직 | fail-closed 유지 · "모를 때"의 시험을 함께 쓴다 |
| 실행 **결과**의 분류 | `lib/classify.mjs` 한 곳이다. 새 갈래는 **여덟 곳**을 함께 만진다 (§1-1) |
| "사람이 쓰는 중인가" 판정 | **pid 로 판정하지 마라.** 재료는 `session-fold` 의 `openTools`·`lastKind`·조용한 시간 (「하지 말 것」) |
| 무인 실행의 권한 | `--dangerously-skip-permissions` 와 같다. 낮추려면 **설정**(`permissionMode`)으로 — 코드의 조건을 지우지 마라 |
| 켬/끔·접기 표시 | 색은 **두 채널**이다 — 스위치(테두리·왼쪽 띠) vs 판정(글자·아이콘). 섞지 마라 (「하지 말 것」) |
| `scripts/*.ps1` · `start.ps1` | **순수 ASCII** — 한글·이모지 금지 |
| 예약 작업 등록 | action 은 `runhidden.exe` 경유 (콘솔 창) |
| `src/ui/*` | 고쳐도 **자동 반영되지 않는다** (아래 2번) |
| `tray.ps1` | `ShowBalloonTip` 금지 · `/api/tray` 만 읽는다 · **UI 스레드를 붙잡지 마라** |
| 프로세스를 띄우는 코드 | `shell: needsShell(exe)` — 무조건 `shell:true` 금지 |
| 상태 파일을 쓰는 코드 | `lib/io.mjs` 의 `원자쓰기`/`덧붙이기` — `writeFileSync` 직접 금지 |
| 락을 만드는 코드 | `{ flag: 'wx' }` — 보고-쓰기는 둘 다 통과시킨다 |
| `src/ui/server.mjs` 의 라우팅 | 새 엔드포인트도 `출처괜찮나`·`세션id인가` 를 거친다 |
| 화면 상단 영역 | 경보(`.alerts-wrap`)를 접히는 `#top` 안으로 옮기지 마라 |
| "돌 수 있나" 판정 | `lib/resume-gate.mjs` **한 곳**이다. 화면도 그것을 쓴다 — 두 벌 만들면 창구마다 다른 말을 한다 |
| 목록의 배지 문구 | **단어**로 쓴다. 문장은 상세의 판정 패널이 맡는다 (§6) |
| `config/*.json` 에 키 추가 | 코드가 **읽어야** 한다. 안 읽는 설정은 `test/config.test.mjs` 가 막는다 |
| 화면이 서버로 보내는 키 | 경로와 본문을 **부르는 자리에 함께** 둬라 — 표로 빼면 대조 시험이 눈을 감는다 |
| 문구를 고칠 때 | `Manual.md` 도 같은 말로 고쳐라 — `test/docs.test.mjs` 가 대조한다 |

## 1. 고친다

주석은 **왜**를 적는다. 실측 근거가 있으면 수치와 날짜를 남겨라 —
이 저장소의 제약은 대부분 사고에서 왔고, 근거가 없으면 다음 사람이 되돌린다.

순수 판정 함수는 IO 와 분리해 둔다. 그래야 시험할 수 있다.

### 1-1. 🔴 새 실패 갈래(`limited`·`auth`·`overload` 같은 것)를 추가할 때

**세 번 다 반쯤만 적용했다** — 제한(09-17) · 과부하 529(09-22) · 인증 만료(09-28).
차단만 풀고 말하는 쪽을 빼먹으면 "재시작을 켜 뒀는데 하루 종일 조용하다"가 새로 생긴다.
여덟 곳을 **한 번에** 만져라:

1. `lib/classify.mjs` — 문구 판정 함수 + `classifyRun` 의 갈래. **순서가 곧 판정이다**
2. `guard.recordRun` — `notOurFault` 에 넣고(연속실패를 올리지 않는다) `...ByDay` 로 센다
3. `resume.mjs` — 스케줄러 이력을 물들이지 않게 `notOurFault` 에 함께 넣는다(exit 0)
4. `lib/session-view.mjs` — `오늘N회` 를 화면으로 내보낸다 (`dayKey()` 로 읽어라, UTC 아니다)
5. `lib/alerts.mjs` — 경보. **꺼지는 조건**을 함께 정한다 (CLAUDE.md §2-1)
6. `src/ui/list.js` — 세션 배지(**단어**로) · `src/ui/detail.js` — 재시작 탭 숫자줄
7. `lib/resume-report.mjs` — `resume --status` 줄
8. `Manual.md` 결과표 · 경보표 + `README.md` — `test/docs.test.mjs` 가 코드와 대조한다

고른 이름은 **되돌릴 수 없다**(옛 기록에 남는다). 옛 값을 읽는 쪽은 계속 받아 줘라 —
`recordRun` 이 한글 `'제한'` 을 아직 받는 이유다. 기록을 버리면 이력이 거짓이 된다.

### 1-1-1. 🔴 «막는 상태»를 만들 때는 **풀리는 길**을 같은 커밋에 넣어라

실측 결함 (2026-09-29): 회로 차단은 `--rearm` 으로만 풀렸다. 그래서 성공한 회차
(`ok · 590초 · 턴 17`) 뒤에도 차단이 남아 **그 뒤 예약 회차가 전부 건너뛰어졌다** —
증명된 멀쩡한 도구가 조용히 죽어 있는 상태다. 차단·잠금·«봐주기» 를 새로 만들면 물어라:

1. **무엇이 이것을 푸는가** — 사람 손 말고. 여기서는 성공 한 번이다(차단 중에 돌 수 있는
   것은 사람이 띄운 회차뿐이라, 그 성공은 `--rearm` 과 같은 증거다).
2. **푼 사실을 기록에 남기는가** — 조용히 풀면 왜 다시 도는지 아무도 모른다.
3. **그 상태를 적는 문장이 사실인가** — 아래 1-1-2.

### 1-1-2. 🔴 상태를 적을 때 **다른 값을 빌려 문장을 만들지 마라**

`연속 ${next.failStreak}회 실패로 회로 차단됨` 은 성공 회차에서 `연속 0회 실패로 회로
차단됨` 이 됐다 — 성공이 `failStreak` 을 0 으로 되돌렸기 때문이다(실측 2026-09-29).
숫자는 맞고 문장은 거짓이다. **그 상태가 들고 있는 이유를 그대로 적어라**
(`blocked.reason` · `blocked.at`). 읽는 사람이 숫자를 믿으면 «0회인데 왜 차단인가» 에서 멈춘다.

### 1-1-3. 🔴 «기다리는 창» 을 만들 때 그 창의 **성질별 길이**를 갈라라

같은 신호처럼 보이는 것이 사실은 둘일 수 있다. 실측(2026-09-28): 도구 결과는 기록에
`type:"user"` 로 들어와 사람의 질문과 구별되지 않았고, 그래서 우리가 타임아웃으로 죽인
회차의 마지막 도구 결과가 「마지막 차례가 사람이다」로 읽혀 **다음 30분을 막았다**
(kill 뒤 다음 회차가 정확히 30.1분 뒤 — 낡음 탈출이 열어 준 시각이다).

- 살아 있는 모델은 도구 결과 뒤 **몇 초** 안에 답한다 → 창은 5분
- 사람의 질문은 답이 오래 걸릴 수 있다 → 창은 회차 시간(`timeoutMin`)

그리고 **설정 값끼리의 관계도 시험으로 못박아라.** `timeoutMin` 을 30 → 60 으로 올렸을 때
`lockStaleMin`(60)이 회차보다 먼저 낡아, 도는 회차의 락을 빼앗을 수 있었다
(`test/config.test.mjs` 가 이제 `lockStaleMin > timeoutMin` 을 지킨다).

### 1-2. 🔴 함수를 다른 파일로 옮겼다면 **가리키던 것**을 함께 옮겨라

`guard.mjs` 가 400줄을 넘어 `classify.mjs` 로 갈랐을 때 남은 것들(실측 2026-09-28):

- `test/docs.test.mjs` 가 `src/resume.mjs` **본문을 읽어** 결과 이름을 대조하고 있었다 →
  과녁이 빈 파일을 가리켜 실패했다. 소스 텍스트를 읽는 시험은 이렇게 조용히 어긋난다.
- `guard.isTransientFailure` 처럼 **옛 위치를 적은 주석·문서가 6곳** 남아 있었다.

옮긴 직후 `grep -rn "<옛파일>\|<옛이름>\."` 로 한 번 쓸어라. 시험이 잡아 주는 것은
운이 좋은 경우다(주석은 아무도 안 잡는다).

### 1-3. 🔴 «우리가 모르는 값» 은 추정하지 말고 **출처를 찾아라**

실측 (2026-09-29): 화면에 `Session (5hr)`·`Weekly (7 day)` 사용률을 넣는데 CLI 가 그 숫자를
주지 않았다. 그래서 «실측 토큰 ÷ 제한 사건에서 배운 기준선» 으로 추정했고, 기준선을 **두 번**
고쳤다(창 종류별로 배우기 → 관측과 어긋나면 스스로 올리기). 결과는 `100%`, 그쪽 값은 `7%`.
**한도의 단위도 창의 시작점도 모르는 값은 분모를 손봐서 맞출 수 없다.** 두 회차를 버렸다.

출처를 찾는 순서 — **네 번째까지 가라:**

1. 하위 명령·플래그 (`claude --help` · `claude <cmd> --help`)
2. 헤드리스 슬래시 명령 (`claude -p /usage --output-format json`) — 결과 **전문**을 찍어 봐라
3. 우리가 이미 읽는 기록 (트랜스크립트의 `quotaLimits` 같은 칸)
4. **CLI 바이너리의 문자열** — 그 화면이 어디서 값을 받는지 그 안에 적혀 있다

```bash
# 239MB exe 도 8MB 씩 latin1 로 읽어 정규식으로 긁으면 몇 초다 (node 로, 셸 확장 없이)
#   /\/api\/[a-zA-Z0-9_\-\/]*usage[a-zA-Z0-9_\-\/]*/g · /utilization/g · /five_hour/g
```

이번에는 4번에서 `/api/oauth/usage` 를 찾았고, 로그인 토큰으로 부르니 사용자가 `/usage` 에서
본 숫자와 그대로 일치했다. 🔴 **못 찾았더라도 답은 추정이 아니라 «없다»** 다 — 절대량만 적고
「정확한 값은 대화 안 `/usage` 에서 보라」고 안내하면 된다. 빈칸은 고장으로 읽히지만,
**그럴듯한 틀린 숫자는 사람이 그것으로 일을 계획하게 만든다.**

그리고 **남의 값을 옮길 때는 그쪽 판정도 함께 옮겨라.** 응답에 `severity` 가 함께 온다.
우리 기준(70%·90%)을 얹으면 그쪽이 `normal` 이라 한 95% 를 우리가 «위험» 이라 부르게 된다 —
경고의 기준을 발명하지 마라. 그쪽이 안 주는 경우에만 우리가 정한다.

### 1-3-1. 🔴 자격증명을 다루면 규칙 넷을 **시험으로** 센다

`~/.claude/.credentials.json` 의 로그인 토큰을 쓰는 코드(`lib/oauth-usage.mjs`)는 이렇게 산다:

1. **새 키를 만들지 않는다** — 로그인된 계정의 토큰만 쓴다(CLAUDE.md §6)
2. **한 호스트에만, 헤더로만** — URL 에 넣으면 기록·프록시에 남는다
3. **어디에도 남기지 않는다** — 돌려주는 값·오류 문구·로그·`state/`. 시험이 토큰 문자열을 찾아본다
4. **우리가 갱신하지 않는다** — 만료면 그렇게 말하고 멈춘다(갱신은 CLI 의 일이다)

문서에 없는 자리를 부를 때는 **실패의 갈래마다** 문구를 따로 둔다(파일 없음 · 만료 · 401 ·
서식 변경 · 그물 끊김). 「못 받았다」 한 마디로 뭉치면 사람이 무엇을 고쳐야 할지 모른다.

### 1-4. 🔴 기계를 걷어냈으면 **잔해도 같은 커밋에서** 지워라

추정 퍼센트를 걷어낼 때 남아 있던 것들: `state/limits.json`(배운 기준선) · 집계의
`quotaByType` 칸 · 시간 통 보관 31일(기준선을 배우려고 늘렸던 값) · 그 이유를 적은 주석 넷.
**쓰지 않는 칸과 주석은 «살아 있는 기능» 으로 읽힌다** — 다음 사람이 그것을 지키려 애쓰고,
캐시는 계속 자란다. 1-2 와 짝이다: 옮길 때는 가리키던 것, 걷어낼 때는 남은 것.

```bash
grep -rn "<걷어낸 이름>" src/ test/ docs/ *.md .claude/   # 주석까지 본다
ls state/ | grep <걷어낸 파일>                              # 런타임 기록도 지운다
```

## 2. 🔴 반영시킨다 — 가장 많이 걸린 함정

```powershell
.\start.ps1 -Restart        # 또는 .\start.exe -Restart
```

**그냥 실행하면 반영되지 않는다.** 서버가 "이미 떠 있음"으로 넘어가는데, 살아 있는
node 프로세스는 **기동 시점의 모듈**을 들고 있다. 화면은 옛 동작을 계속 보여주고
아무도 경고하지 않는다. 이 저장소를 만드는 동안 두 번 걸렸다.

`.ps1` 이나 `tools/*.cs` 를 고쳤다면 exe 부터 다시 만든다:

```powershell
.\scripts\build-exe.ps1     # start.exe + runhidden.exe
```

예약 작업의 action·설정을 고쳤다면 **재등록**해야 한다. 단순 재시작으로는 안 바뀐다:

```powershell
.\scripts\register-ui.ps1        # 포트를 먼저 비우고 등록 후 응답까지 확인한다
.\scripts\register-heartbeat.ps1
.\scripts\register-resume.ps1
.\scripts\register-tray.ps1
```

## 3. 시험한다

```bash
npm test        # node --test test/*.test.mjs
```

ASCII 가드가 가장 자주 잡는다(`.ps1` 의 한글·이모지). 이 저장소를 만드는 동안
**세 번** 걸렸다 — 사람 손을 믿지 마라. 실패하면 비ASCII 줄 번호를 알려준다.

그다음으로 자주 잡는 것이 **400줄 규칙**이다(`test/line-limit.test.mjs`, 저장소 전체를 잰다).
한 회차에 여섯 번 걸렸다 — `README.md`·`Manual.md`·`guard.mjs`·`sessions.mjs`·`app.css`·
`guard.test.mjs`. 문서도 센다. 넘겼다는 것은 **쪼갤 자리가 생겼다**는 신호다:
주석을 지우지 말고 관심사로 갈라라(예: 토글 색 규칙은 `app.css` → `fold.css` 로 옮겼다).

새 판정 로직을 넣었으면 **"모를 때"의 시험을 반드시 함께** 쓴다:
값이 없을 때 · 파일이 깨졌을 때 · 프로세스가 죽었을 때 각각 "안 된다"로 답해야 한다.

### 3-0. 🔴 새 시험은 **결함을 되살려** 실패하는지 확인한다

통과하는 시험은 아무것도 증명하지 않는다. 고친 것을 되돌려 놓고 **그 시험이 정말
빨개지는지** 본 다음에 다시 고쳐라. 이 저장소에서 두 가지가 그렇게 드러났다:

- 인증 회차를 고치며 "판정 순서가 뒤집히면 401 이 `fail` 로 돌아간다"고 주석에 적었다.
  순서를 실제로 뒤집어 보니 **아무 시험도 실패하지 않았다** — `isTransientFailure` 가
  401 을 이미 배제하므로 순서가 아니라 **칸의 유무**가 문제였다. 주석과 시험을 함께
  고쳤다. 주입해 보지 않았다면 틀린 근거가 남아 다음 사람을 오도했을 것이다.
- `test/ui-layout.test.mjs` 의 정규식이 템플릿 문자열 안에서 `\s` 였다(그냥 `s`).
  `s*` 는 빈 것도 맞아 **우연히 통과**하고 있었다. `padding: 9px` 를 일부러 넣어
  잡히는 것을 확인하고서야 검사기가 산다는 것을 알았다.

> 🔴 이 환경의 heredoc(`cat <<'EOF'`)은 `\\` 를 `\` 로 먹는다. 정규식이 든 JS 는
>   **Write/Edit 도구로 써라.** 그렇게 들어간 `\s` 는 문법 오류가 아니라 **조용한 오답**이다.

### 3-0-1. 🔴 파일 내용을 **셸을 거쳐** 고치지 마라 (`node -e` 도 셸이다)

실측 (2026-09-28): `node -e "…replace('| 4 | … \`--force\` …')…"` 로 Manual 의 표를 고쳤는데,
큰따옴표 안의 **백틱이 명령 치환으로 먹혀** 그 조각만 사라졌다. 결과가 이렇다:

```text
| 4 | **그 세션이 일하는 중이다** (배지 ) | …  로도 안 뚫린다 …   ← 백틱 안이 통째로 비었다
```

문법 오류가 없으니 아무도 경고하지 않고, 표는 멀쩡해 보인다. 세 줄을 손으로 되살렸다.
**백틱·`$`·`\` 가 든 내용은 Write/Edit 로 쓴다.** `node -e` 는 경로와 숫자만 다룰 때 쓴다.

### 3-1. 🔴 시험이 깨졌을 때 — 먼저 "무엇을 지키던 시험인가"를 읽어라

리팩터가 시험을 **조용히 약하게** 만들 수 있다. 실측:

- 동작줄을 `apply(...)` 로 감쌌더니 "화면이 보내는 키를 서버가 받나" 대조가 POST 를
  **6개만** 읽었다. `assert.ok(posts.length >= 8)` 라는 하한선이 그것을 잡았다 —
  숫자를 낮추는 것이 아니라 **읽는 방법**을 고치는 것이 답이었다.
- `Keep-One` 으로 묶으니 `Show-Window` 를 직접 찾던 시험이 깨졌다. 계약(앞으로
  가져오고 `exit 0`)으로 바꾸고, **미룬 것이 사라지지 않았는지**도 함께 확인했다.

그러니 깨진 시험을 고칠 때 **왜 그 모양이었는지**를 먼저 읽어라. 통과하게 맞추는 것은
쉽고, 그렇게 고치면 지키던 것이 없어진다.

### 3-2. 🔴 하네스가 껍데기면 시험은 헛돈다

`test/_ui-harness.mjs` 의 가짜 DOM 은 실제로 움직여야 한다. 실측: `classList` 가
`toggle() {}` 였고 `localStorage` 는 늘 `null` 을 돌려줬다. 접힘은 **클래스로만**
표현되고 **기억되는 것이 요점**이라, 그 둘이 껍데기인 동안은 눌러 봐도 전부 통과했다.
둘을 진짜로 만들자 곧 두 가지가 드러났다(모듈에 캐싱한 접힘 사본 · 순서에 기댄 시험).

**새 화면 기능이 클래스나 저장소에 기대면, 하네스가 그것을 정말 흉내내는지 먼저 봐라.**

### 3-3. 🔴 시험을 **순서에 묶지 마라**

실측 (2026-09-29): 화면 시험이 `assert.equal(calls.length, 2)` 로 호출 수를 세고 있었다.
앞에 시험 하나를 끼우자 3이 되어 깨졌다 — 계약(«누르면 한 번 더 부른다»)은 그대로인데.

```js
const before = calls.length      // 차이로 본다
await press()
assert.equal(calls.length, before + 1)
assert.equal(calls.at(-1), '/api/usage?fresh=1')
```

같은 부류: 배열 첫 칸을 `[0]` 으로 집는 것(`at(-1)` 을 써라) · 모듈 전역 상태를 시험마다
비우지 않는 것(`prepareRender()` 가 그 일을 한다).

## 4. 검증한다 — "등록됨"과 "돌고 있음"은 다르다

```powershell
.\start.exe -Status
```

네 가지를 각각 확인하라. 하나만 보면 틀린 결론에 간다:

1. **예약 등록** — 없으면 세션 밖에서 아무것도 돌지 않는다
2. **실제 응답** — 서버가 127.0.0.1:7345 에 답하는가, 트레이 뮤텍스가 잡혀 있는가
3. **기록 신선도** — `--check` (fail-closed, 낡으면 exit 1)
4. **콘솔 창** — 아래 §5 (`windows-traps.md`)

이 저장소를 만들며 **가장 여러 번 속은 자리**이고 전부 Windows 특유의 것이라 따로 뒀다:

### 🔴 `npm test` 와 `git commit` 을 **한 줄로 묶지 마라**

실측 (2026-09-28): `npm test | grep … && git add -A && git commit …` 으로 한 번에 실행해서
**빨간 시험을 그대로 커밋했다**(`Manual.md` 402줄, line-limit 실패). `grep` 이 0 을 돌려주니
`&&` 가 통과한 것이다 — 검사를 **돌린 것**과 결과를 **읽은 것**은 다르다.

```bash
npm test                     # 먼저 돌리고, 통과를 눈으로 확인한다
git add -A && git commit …   # 그다음에 커밋한다 (별도 명령으로)
```

커밋 메시지에는 **무엇을 왜 고쳤는지와 실측 근거**를 적는다. 이 저장소의 이력은
다음 사람이 제약을 되돌리지 않게 막는 유일한 장치다.

## 하지 말 것 — 되돌리면 사고가 재발한다

- `heartbeat.mjs` 에 `--loop`·`setInterval` 을 넣지 마라 (9시간 중단의 원인)
- 판정을 fail-open 으로 바꾸지 마라 ("모르면 정상"은 감시가 아니다)
- 목록이 비었다고 "아무도 안 돈다"로 읽지 마라 — `ok` 를 함께 봐라 (조회 실패가 가드를 열었다)
- `tray.ps1` 에 `ShowBalloonTip` 을 되살리지 마라 (알림은 화면에서)
- 트레이 타이머에서 동기 HTTP 를 부르지 마라 (메뉴가 최대 2.7초씩 얼었다)
- UI 바인드 주소를 `0.0.0.0` 으로 바꾸지 마라 (재시작을 띄울 수 있는 화면이다)
- Origin 검사를 빼지 마라 (아무 웹페이지나 `/api/run` 을 누를 수 있었다)
- 상태 파일을 `writeFileSync` 로 직접 쓰지 마라 (찢어지면 감시가 통째로 멈춘다)
- 단일 실행 락을 걷어내지 마라 (예약의 `MultipleInstances` 는 스케줄러끼리만 막는다)
- API 키를 도입하지 마라 (VS Code 에 로그인된 계정을 쓴다)
- **화면이 제 나름대로 판정하게 하지 마라** — 예산만 보고 "재시작 준비"라고 말했고,
  실제로는 여덟 가지가 더 막았다. 켜 두고 자리를 비웠는데 아무것도 안 돌았다.
  **없는 것을 있다고 말하는 것은 있는 것을 없다고 하는 것만큼 나쁘다.**
- **설정 상태와 지금 상태를 한 배지에 뭉개지 마라** — `재시작 꺼짐` 과 `재개 안 함` 은
  다른 축이다. 번갈아 내보내니 누른 것이 먹혔는지 알 수 없어 "적용이 안 된다"는 말이
  나왔다(등록부에는 8초 전에 써져 있었다). **켬/꺼짐을 항상 앞에** 둬라.
- **목록의 배지에 문장을 넣지 마라** — 한 줄이 배지 하나로 가득 차 옆 배지가 밀려난다.
  단어로 훑게 하고, 문장은 상세의 판정 패널에 둬라. 다만 **단어로 줄이면서 근거를
  버리지 마라** — hover(title)와 판정 패널 양쪽에 남겨라(hover 에만 두면 안 된다).
- 누른 결과를 말하지 않고 넘기지 마라 — 반응 없는 화면은 고장난 화면과 구별되지 않는다.
  `post()` 는 **실패해도 본문을 돌려준다**(`null` 은 연결 실패뿐). `error` 를 먼저 봐라.
- 읽지 않는 설정 키를 남기지 마라 (고쳐도 아무 일이 없는데 사람은 바뀐 줄 안다)
- **모르는 값을 추정해서 화면에 올리지 마라** — 「실측 ÷ 배운 기준선」으로 만든 사용률이
  `100%` 를 가리켰고 그쪽 값은 `7%` 였다. 출처를 찾아라(§1-3). 못 찾으면 **«없다» 고 적어라.**
- **남의 숫자에 우리 경고 기준을 얹지 마라** — 응답의 `severity` 를 따르고, 없을 때만 정한다.
- **자격증명을 로그·상태·반환값에 흘리지 마라** (§1-3-1: 헤더로만 · 한 호스트 · 갱신 금지)
- **차단을 풀었으면 침묵하지 마라** — 연속실패로 세지 않기로 한 실패는 하루 횟수를
  세고 배지·경보로 말해야 한다. 세 번 다 이 절반을 빼먹었다 (§1-1)
- 새 경보에 **꺼지는 조건**을 안 주지 마라 — 낫고 지나간 일을 계속 외치면 늑대 외치기다.
  그리고 «끊겼다»와 «모른다»를 같은 수준으로 말하지 마라 (치명 vs 경고)
- 조각끼리 `import` 하지 마라 — 400줄 때문에 쪼갤 때 가장 밟기 쉽다. 새 파일이 다른
  조각을 가져오면 `ui-modules` 시험이 잡는다. 같은 관심사면 **같은 조각**에 둬라.
- `setup.js` 에 부작용(폴링·바인딩)을 넣지 마라 — 하네스가 그 성질 위에 서 있다.
- **pid 로 "사람이 쓰는 중"을 판정하지 마라** — 창만 열어 둬도 프로세스는 살아 있다.
  그렇게 읽어 560회 연속 건너뛰었다(2026-09-22~09-28). 재료는 그 세션의 기록이다.
- **비용으로 재개를 막지 마라** — 통계·참고선이다(사용자 결정 2026-09-28). 상한은 띄우기
  전에만 보므로 한 회차가 넘는 것을 못 막았다(참고선 $5, 한 회차 $18.271). 횟수가 묶는다.
- **실행 직전 재판정을 걷어내지 마라** — 판정과 실행 사이에도 시간이 흐른다. 락을 잡은 뒤
  최신 집계로 다시 판정하고, 뒤집혔으면 띄우지 않는다. UI 의 '지금 실행' 도 같은 진입점에
  `--dry-run` 으로 먼저 물어본다(판정을 두 벌 만들지 않는다).
- **색을 판정에만 쓰지 마라** — 배지는 두 가지를 말한다(스위치가 켜졌나 · 지금 어떤가).
  한 채널에 몰면 `켬·대기` 와 `꺼짐` 이 구별되지 않는다(실측 지적). 스위치는 테두리·왼쪽 띠,
  판정은 글자·아이콘. 그리고 **색만으로 나르지 마라** — `켬`/`꺼짐` 이라는 말을 함께 둔다.
- 접기 토글의 색을 조각마다 칠하지 마라 — `[aria-expanded]` 에 걸어 두면 새 토글도
  자동으로 같은 규칙을 받는다. 손으로 칠하면 반드시 하나가 빠진다.

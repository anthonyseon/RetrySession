# RetrySession

Claude Code 세션을 **세션 바깥에서** 감시하고 재시작한다. 의존성 없음 — `node` 만 있으면 돈다.

**쓰는 법은 [`Manual.md`](./Manual.md) 에 있다** — 화면 읽는 법 · 재시작이 안 도는 이유 찾기 ·
경보별 대처 · 명령 요약. 이 문서는 **왜 그렇게 만들었는지**를 적는다.

## 이것이 푸는 문제

Claude Code 세션이 닫히면 그 안에서 돌던 것은 전부 멈춘다. 세션 안 예약(cron)도 함께 멈춘다.
그래서 "중단되면 이어서 하기"를 세션 안에 두면, 정작 중단됐을 때 아무도 깨워주지 못한다.

앞선 계획에서 실제로 겪은 일이다:

> **2026-09-16 23:02 ~ 09-17 08:04 (9시간)** `setInterval` 이 멈춰 기록이 끊겼다. 예약도 같은 구간에 발동 0건.
> 절전 아님(Kernel-Power 0건) · 재부팅 아님(가동 46.6h) · 프로세스 사망 아님(PID 28472 생존).
> **PC 는 깨어 있었고 프로세스도 살아 있었는데 타이머만 멈췄다.**

그때 대책으로 기록만 OS 작업 스케줄러로 옮겼지만, 비대칭이 남았다 —
**기록은 바깥에 있는데 재개는 여전히 세션 안이나 사람 손에 있었다.**
RetrySession 은 그 비대칭을 없앤다. 감시와 재시작 **둘 다** OS 에 둔다.

## 세 가지 트리거

| # | 무엇 | 어디서 도는가 | 주기 |
|---|------|--------------|------|
| ① | **감시** — 어디까지 왔는지 디스크에 기록 | OS 작업 스케줄러 `EasyAI-RetrySession-Heartbeat` | 5분 |
| ② | **재시작** — `claude --resume` 로 실제로 이어서 진행 | OS 작업 스케줄러 `EasyAI-RetrySession-Resume` | 15분 |
| ③ | **UI** — 실시간 상태 화면 | OS 작업 스케줄러 `EasyAI-RetrySession-UI` | 로그온 시 |
| ④ | **트레이** — 상태 점 + 변화 시 알림 | OS 작업 스케줄러 `EasyAI-RetrySession-Tray` | 로그온 시 |

넷 모두 **Claude Code 세션과 무관하게** 돈다. 세션을 닫아도, VS Code 를 닫아도 계속 돈다.

**장수 타이머를 쓰지 않는다.** 5분마다 OS 가 새 프로세스를 띄운다 — 얼어붙을 타이머 자체가 없다.
그래서 `heartbeat.mjs` 에는 `--loop` 이 없다. 다시 넣지 마라. 그게 9시간 중단의 원인이었다.

## 시작하기

**`start.exe` 를 더블클릭하면 된다.** 처음 한 번만 빌드한다:

```powershell
.\scripts\build-exe.ps1     # start.exe 생성 (Windows 내장 csc.exe, 1초)
.\start.exe -Install        # 처음 한 번 — OS 작업 등록 + 바로가기 + 창 열기
.\start.exe                 # 그 뒤로는 더블클릭 (또는 이 명령)
```

`start.exe` 는 `start.ps1` 을 부르는 8KB 짜리 런처다. `.ps1` 은 더블클릭해도 실행되지
않고 편집기로 열리며, `.bat` 은 콘솔 창을 번쩍인다 — 그래서 `/target:winexe` 로 만든
진짜 exe 를 쓴다. **콘솔 창이 뜨지 않고 `cmd.exe` 를 거치지 않는다.**
터미널에서 인자와 함께 부르면 출력은 그 터미널에 그대로 나온다.

exe 없이 `.ps1` 을 직접 써도 똑같다:

```powershell
.\start.ps1 -Install        # 처음 한 번 — OS 작업 등록 + 바로가기 + 창 열기
.\start.ps1                 # 서버·트레이 확인하고 창을 연다
.\start.ps1 -Status         # 상태만 출력
.\start.ps1 -Restart        # 🔴 src\ 를 고친 뒤 (아래 참조)
.\start.ps1 -Stop           # 서버·트레이 중지 (예약은 남아 다음 로그온에 다시 뜬다)
.\start.ps1 -Uninstall      # OS 작업 전부 해제 (state\ 는 남는다)
```

`-Install` 은 기본으로 **재시작을 등록하지 않는다.** 사람 없이 토큰을 쓰고 파일을 고치는
일이라 `-Install -WithResume` 이라고 명시해야 한다.

> **🔴 `-Restart` 가 왜 필요한가** (실측 함정)
> 그냥 실행하면 서버가 "이미 떠 있음"으로 보고 그대로 둔다. 그런데 살아 있는 node 프로세스는
> **기동 시점의 모듈을 들고 있다.** 그래서 `src\` 를 고쳐도 화면은 옛 동작을 계속 보여주고
> 아무도 경고해주지 않는다. 실제로 이 작업 중에 겪었다 — `-Restart` 가 포트를 비우고 새로 띄운다.

세션을 고르고 감시·재시작을 켜는 것은 창에서 한다. 개별 명령이 필요하면:

```bash
npm test          # 판정 로직·단가·ASCII 규칙·이름 규칙·설정 무결성이 여기 고정돼 있다
npm run check     # 기록이 살아 있나 (fail-closed, 낡으면 exit 1)
npm run list      # 감시·재시작 대상 목록
npm run resume:dry    # 재시작 가드만 판정 (띄우지 않고 지시문도 보여준다)
npm run resume:status # 예산·마지막 실행
```

## GUI

브라우저 탭이 아니라 **단독 앱 창 + 트레이 아이콘**으로 쓴다.

```powershell
.\scripts\open-app.ps1              # 주소창·탭 없는 앱 창으로 열기
.\scripts\shortcut.ps1 -Desktop     # 시작 메뉴 + 바탕화면 바로가기
.\scripts\register-tray.ps1         # 트레이 아이콘 상주
```

- **앱 창** — Edge/Chrome 의 `--app` 모드다. 주소창·탭이 없고 작업표시줄 아이콘이 따로 잡혀
  고정할 수 있다. 전용 `--user-data-dir` 을 쓰므로 평소 브라우저 세션과 섞이지 않는다.
- **트레이** — 상태를 색 점으로 보여주고, 상태가 **바뀔 때만** 풍선 알림을 띄운다
  (감시 끊김 · 재시작 차단 · 사용량 제한 · 서버 응답 없음). 더블클릭으로 창을 열고,
  우클릭 메뉴에서 지금 감시 실행·예약 상태 보기·종료를 할 수 있다.
- **콘솔 창이 뜨지 않는다.** 예약 작업은 `runhidden.exe` 를 거쳐 node 를 띄운다(`cmd.exe` 도 거치지 않는다).

  > 🔴 실측 함정: 예약 작업의 `-Hidden` 설정은 **작업 스케줄러 목록에서 작업을 숨기는**
  > 옵션이지 프로세스 창을 숨기지 않는다. action 을 `node.exe` 로 두면 대화형 로그온에서
  > `conhost.exe` 가 붙어 **콘솔 창이 계속 떠 있는다**(UI 서버는 영원히 돌므로 창도 영원히
  > 남고, 5분마다 도는 감시는 5분마다 번쩍인다). `/target:winexe` 로 만든 `runhidden.exe`
  > 가 `CREATE_NO_WINDOW` 로 자식을 띄워 그 창을 없앤다.

- **알림은 Windows 풍선으로 띄우지 않는다.** 트레이는 색·툴팁·메뉴로 **상태만** 나르고,
  경보와 그 이력은 창에서 본다. 풍선은 상태가 조금만 오르내려도(서버 재시작 한 번에 두 번)
  떠서 진짜 경고를 묻어버렸다. 화면 맨 위 배너에 뜨고, 세션에 딸린 경보는 눌러서 바로 그
  세션 상세로 간다. 창을 닫아둔 사이의 변화는 감시가 5분마다 확인해 **바뀔 때만** 남긴다.

## 중복 실행 금지

구성요소마다 **하나만** 돈다.

| 구성요소 | 장치 | 낡은 잠금 회수 |
|---|---|---|
| 감시 · 재시작 · UI | `state/locks/<이름>.lock` (pid + **프로세스 시작 시각** + 잡은 시각) | 30분 · 90분 · 24시간 |
| 트레이 | Windows 명명 뮤텍스 | pid 가 죽으면 즉시 |

예약 작업의 `MultipleInstances IgnoreNew` 는 **스케줄러가 띄우는 것끼리만** 막는다.
사람이 손으로 돌리거나 창·트레이에서 "지금 실행"을 누르면 예약 실행과 겹칠 수 있고,
그러면 같은 `heartbeat.json` 을 동시에 덮어써 기록이 찢어지거나 하루 예산을 두 배로 쓴다.
그 구멍을 락이 막는다.

**중복은 오류가 아니다.** 이미 돌고 있어서 안 도는 것은 정상이므로 이유를 적고 `exit 0`
으로 끝낸다 — `1` 로 끝내면 작업 이력이 빨갛게 물들어 진짜 실패를 가린다.

락은 pid 생존과 시간 한계를 **둘 다** 본다. pid 는 재사용되므로 그것만 믿을 수 없고,
시간만 보면 멀쩡히 도는 것을 밀어낸다. 강제 종료로 남은 잠금은 pid 확인이 받아낸다.

pid 가 **재사용된** 경우까지 가리려고 락에 프로세스 시작 시각을 함께 적는다. 확인은
**거절하기 직전에만** 한다(PowerShell 1회, 실측 649ms) — 화면이 3초마다 부르는
`lockState` 에 넣으면 `taskState` 가 `/api/ping` 을 7.9초로 만든 사고가 재현된다.
확인에 실패하면 **그대로 둔다**(fail-closed) — 못 물어봤다고 남의 락을 깨면 중복을 허용한다.

> **왜 Electron 이 아닌가** — 이 도구는 *다른 게 다 멈췄을 때 살아 있어야 하는* 감시 장치다.
> `npm install` 이 필요한 형태는 정작 필요한 순간에 못 뜬다. 그래서 의존성 0 을 지킨다.
> 트레이는 Windows 에 내장된 WinForms 를 쓰고, 아이콘은 실행 시에 그린다(`.ico` 자산 없음).

## UI

`http://127.0.0.1:7345` — **로컬 전용이다.** 이 화면은 재시작을 띄울 수 있으므로 바인드 주소를 바꾸지 마라.

- **세션 목록** — 다중 선택해서 감시·재시작을 한꺼번에 켜고 끈다. 실행 중 여부(pid) · 활동 시각 · 사용량 `오늘`/`누적` 두 줄(턴·도구·토큰·정가)
- **상세** — 선택한 세션의 처리 상황·대화·도구 호출을 2초마다 갱신. 감시 로그 · 재시작 로그 · 재개지시 설정
- **사용량** — 계정·구독, 오늘·누적 합계, 모델별 토큰과 정가 환산, 사용량 제한 상태와 해제 시각
- **OS 트리거** — 네 작업(감시·재시작·UI·트레이)의 등록 여부·마지막 결과·다음 실행

화면 오른쪽 위에 **"n초 전 갱신"** 이 항상 떠 있다. 화면이 멈추면 바로 알 수 있어야 한다.

### 🔴 화면은 재개가 내릴 판정을 **그대로** 보여준다

실측 결함 (2026-09-22): 목록의 재시작 배지가 **예산만** 보고 `재시작 준비` 라고 말했다.
실제로는 여덟 가지가 더 막는다(실행 중·재개 지점 없음·저장소 잠금·조용한 시간·제한·
활동·차단·추적기 전부 done). 그래서 사람은 "준비"를 믿고 자리를 비웠는데 15분마다
조용히 건너뛰었고, "켰는데 왜 안 도는가"를 반복해서 물었다.
**없는 것을 있다고 말하는 것은 있는 것을 없다고 하는 것만큼 나쁘다.**

판정은 [`lib/resume-gate.mjs`](./src/lib/resume-gate.mjs) **하나**다(순수 함수).
재개가 그것으로 정하고, 화면은 같은 것을 옮긴다 — 규칙이 두 벌이면 창구마다 다른 말을 한다.
상세의 재시작 탭 맨 위에는 판정 패널과 **고치는 단추**가 있다(`재개지시 넣기` · `차단 해제`).

### 🔴 배지는 스위치와 상태를 **함께** 말한다

판정을 그대로 내보내면서 한 번 더 다쳤다. `⊘ 재개 안 함 · 세션이 실행 중이다` 로만
보여줬더니 사용자가 "적용이 안 되는 것 같다"고 했다 — **설정은 제대로 됐고**(등록부
mtime 이 8초 전) 화면이 그 사실을 말하지 않은 것이었다.
`재시작 꺼짐` 과 `재개 안 함` 은 **다른 축의 말**인데 같은 자리에 번갈아 나오니,
누른 뒤에도 변화가 보이지 않았다.

그래서 켬/꺼짐이 **항상 앞에** 온다: `○ 재시작 꺼짐` · `◔ 재시작 켬 · 지금은 대기 — …` ·
`● 재시작 켬 · 재개 가능 (…)`. 사람이 풀어야 하는 것(차단)만 `▲` 를 쓴다 —
기다리면 되는 것에 경고를 쓰면 진짜 경고가 묻힌다.
그리고 누른 결과를 동작줄에 적는다(`✅ 3개 — 재시작을 켰습니다 (그중 3개는 … 대기)`).

> 🔴 `post()` 는 **실패해도 본문을 돌려준다**(`null` 은 연결 실패뿐). 그것을 성공으로
> 읽으면 "✅ 적용됐습니다" 라고 거짓말하게 된다 — 결과를 말하는 코드는 `error` 를 먼저 본다.

### 영역마다 접힌다 · 너비는 드래그로

요약 다섯 묶음이 각각, 열린 폴더 묶음도 접힌다(머리줄 클릭 · Enter). 접힘은 기억된다.
**접어도 요지는 남긴다** — 접힌 것이 "없는 것"으로 보이면 감시 장치가 스스로 눈을 가린다.
경보는 접히지 않는다. 접은 채로 '감시 끊김'이 숨으면 이 도구가 막으려는 일이 일어난다.

세션과 상세 사이의 손잡이를 끌면 **너비가 바뀐다**(`ui/layout.js`).
세션 영역은 머리줄의 `▾` 로 **34px 세로 띠로 접힌다** — 그 띠에도 `세션 n개` 는 남는다.
고정 비율이었을 때는 목록을 훑을 때와 로그를 읽을 때 중 한쪽이 늘 좁았고,
창을 하나만 띄우는 도구라 둘을 벌려 비교할 수도 없었다.

- 한쪽이 사라질 만큼은 못 끈다(세션 ≥320px · 상세 ≥420px). 되돌릴 길을 준다 — 더블클릭.
- 키보드로도 조절된다(`role=separator` · `←/→` · `Shift` · `Home`).
- 창이 좁아지면 저장된 너비를 **다시 자른다.** 320+420 이 안 들어가면 비율에 맡긴다.
- 🔴 좁은 화면(≤1100px)에서는 `grid-template-columns:1fr !important` 로 드래그가 남긴
  inline 격자를 **무시**한다. 안 그러면 세로로 쌓인 뒤에도 한 칸이 화면을 넘어간다.

> 🔴 `Number(null)` 은 `0` 이고 `Number.isFinite(0)` 은 참이다. "저장된 값 없음"을
> 그냥 넘기면 0 이 최소값으로 잘려 **새로 깐 화면이 CSS 비율 대신 320px 로 굳는다.**
> 없는 것과 0 은 다르다 — 시험이 이것을 잡았다.

> 🔴 화살표는 CSS `::after` 로만 그린다. `h3` 안에 글자로 넣으면 묶음 이름이 `▾계정` 이
> 되어 이름으로 찾는 코드와 시험이 조용히 어긋난다.

## 인증과 비용

**VS Code 에 로그인된 Claude Code 계정을 그대로 쓴다.** API 키를 쓰지 않는다.
그래서 예약 작업은 **같은 Windows 사용자 · Interactive 로그온**으로 등록된다 —
`%USERPROFILE%\.claude` 의 자격증명을 읽어야 하기 때문이다. 실행 환경에서
`ANTHROPIC_API_KEY` 계열을 비워 계정 프로필이 항상 이기게 한다.

사용량(턴·도구·토큰·정가)은 **오늘(로컬 자정 기준)과 누적으로 갈라** 보여준다. `오늘` 은 언제나 `누적` **이하**다 — 첫날이면 같고 이틀 이상 걸쳐 썼으면 적다.
오늘 몫은 캐시에 통 하나로만 들고 다니므로 자정 뒤엔 읽는 쪽이 0 으로 답한다(UTC 로 세면 9시간이 어제가 된다).

화면의 금액은 **정가 환산 참고값**이다. 구독(`max`)이면 실제 청구액이 아니다.
토큰 수는 트랜스크립트 실측이고, 환산은 실측 검증된 단가를 쓴다:

| | 단가 | 근거 |
|---|---|---|
| 입력 | $5.00 / 1M | 정가표 (claude-opus-5) |
| 출력 | $25.00 / 1M | 정가표 |
| 캐시 쓰기(1h) | 입력 × 2 | **실측 역산** |
| 캐시 읽기 | 입력 × 0.1 | **실측 역산** |

`claude -p --output-format json` 의 `total_cost_usd` 와 우리 계산이 **오차 0** 으로 맞는다(표본 2건, `test/pricing.test.mjs`). 단가는 `config/pricing.json` 에서 고친다.

> `claude -p` 1회는 아무 일도 안 해도 최소 **~$0.21** 든다(시스템 프롬프트 캐시 21k 토큰이 매 프로세스마다 새로 잡힌다).
> 🔴 **비용은 재개를 막지 않는다** — 통계·참고선이다(상한은 띄우기 전에만 보므로 한 회차가 넘는 것을 못 막았다. 실측: 참고선 $5, 한 회차 $18.271). 지출은 `maxPerDay`·`timeoutMin` 이 묶는다.

## 재시작이 실행되지 않는 조건

사람이 보고 있지 않은 실행이다. 가드를 **전부** 통과해야만 `claude --resume` 이 뜬다.

1. UI 에서 그 세션의 재시작이 켜져 있는가
2. **이 저장소가 자율 재개를 허용하는가** — `config/projects.json` 의 `resume.enabled` (기본 `false`, 저장소 단위 잠금이라 `--force` 로도 안 뚫린다)
3. 조용한 시간이 아닌가 (`quietHours`, 기본 끔)
4. **그 세션이 일하는 중이 아닌가** — 도구가 결과를 기다리지 않고, 마지막 차례가 모델인가(답이 나왔나).
   `--force` 로도 못 뚫고, 활동 시각을 못 읽으면 막는다(`확인불가`). 🔴 **pid 로 판단하지 않는다** —
   창만 열어 둬도 프로세스는 살아 있어서, 그것을 "쓰는 중"으로 읽어 **560회 연속** 건너뛴 적이 있다.
   차단에도 끝이 있다(30분 넘게 조용하면 죽은 도구로 본다). 조건 전체는 Manual §5-1.
5. 최근 N분 활동이 없는가 (기본 3분 · sessionActiveMin)
6. **재개 지점이 있는가** — 넷 중 하나: 추적기의 `doing`/`todo` · 재개지시 · 제한에 잘린 자리 ·
   **끊긴 자리**(절전·네트워크). 하나도 없으면 무엇을 이어서 할지 정해지지 않은 것이라 돌지 않는다.
   잘린 자리는 추적기의 "전부 done" 보다 우선하고, 끊긴 자리는 **한 번만** 이어 본다.
7. 사용량 제한 중이 아닌가 — `--force` 로도 건너뛸 수 없다
8. 예산 — 하루 **횟수**(12) · 최소 간격(30분) · 연속 실패 차단(3회). 🔴 **비용은 막지 않는다**(통계·참고선)
9. 세션별 락 — 두 개가 같은 대화에 쓰지 않게

막힌 이유가 **같은 이유로 이어지면 로그는 접힌다** (`SKIP ×4 (처음 …)`) — 15분마다
같은 줄이 쌓이면 사람이 안 읽게 되고, 안 읽는 기록은 없는 것과 같기 때문이다.

실패했을 때도 **다 우리 실패가 아니다.** 사용량 제한(`limited`) · 로그인 끊김(`auth`) ·
API 과부하(`overload` — 529·5xx)는 연속 실패로 세지 않는다 — 기다리면 풀릴 일에 회로를
차단하면 저쪽이 멀쩡해진 뒤에도 사람 손을 부르게 된다. 다만 **0으로 되돌리지도 않고**
조용히 넘기지도 않는다 — 몇 번 막혔는지 배지에 세고 잦아지면 경보로 올린다
(결과 이름은 `classify.classifyRun` 한 곳에서 정한다).

막힌 것은 이유를 로그에 적고 **exit 0** 으로 끝낸다. 스케줄러 이력이 실패로 더러워지지 않게.

재개 지시문에는 항상 이 두 줄이 들어간다:

- 판단이 갈리는 지점에서는 **멈춘다.** 추측으로 진행하지 않는다.
- 되돌리기 어려운 작업은 하지 않는다: force push · 브랜치 삭제 · 파일 대량 삭제 · 외부 전송

## 판정은 fail-closed 다

> **감시 장치가 "모르면 정상"이라고 답하면 감시가 아니다.**

실측 사고: 임시로 쓴 하트비트 판정이 `atEpoch` 가 없을 때 "살아있음"으로 답했고,
실제로는 9시간 낡은 상태였다. 그 fail-open 때문에 중단을 놓쳤다.

그래서 모든 판정은 "모르면 안 된다"로 답하고, `test/guard.test.mjs` 가 그것을 고정한다 —
파일이 없으면 죽음, 상태가 깨졌으면 예산 거부, 조용한시간 형식이 틀리면 조용한 시간,
세션 활성을 모르면 재시작 금지.

## 작업 절차 (Claude 스킬)

이 저장소에만 적용되는 절차를 스킬로 두었다. 불변 규칙은 [`CLAUDE.md`](./CLAUDE.md) 가
정본이고, 스킬은 **순서와 명령**을 담는다.

| 스킬 | 언제 |
|---|---|
| `retrysession-change` | `src/`·`scripts/`·`tools/` 를 고치거나 예약 작업을 바꿀 때 |
| `retrysession-diagnose` | 감시·재시작·화면이 안 돌거나, 세션이 목록에 없거나, 콘솔 창이 뜰 때 |

스킬이 가리키는 스크립트·`npm` 명령·`start` 스위치가 실재하는지는
`test/skills.test.mjs` 가 확인한다 — 틀린 안내는 없느니만 못하다.

**왜 `hb.mjs` / `rs.mjs` 가 따로 있나** — PowerShell 5.1 은 `.ps1` 을 ANSI 로 읽어서 한글이
들어가면 파서가 죽는다(실측). 스케줄러가 건드리는 경로는 ASCII 여야 한다.
`test/ascii.test.mjs` 가 이 규칙을 기계로 지킨다 — 이 도구를 만드는 중에도 한 번 어겼기 때문이다.

## 정보를 어디서 읽는가

CLI 가 주는 것은 CLI 로 얻고, 없는 것만 파일에서 읽는다. CLI 는 공식 인터페이스고 파일은 내부 구조다.

| 출처 | 주는 것 |
|---|---|
| `claude agents --json` | 실행 중 세션 — pid · cwd · kind · startedAt · name |
| `claude auth status --json` | 계정 — email · orgName · subscriptionType · authMethod |
| `~/.claude/projects/*/*.jsonl` | 토큰 · 모델 · 제목 · 도구 호출 · 대화 · `quotaLimits` |
| `schtasks /Query` | OS 예약 등록 여부 · 마지막 결과 |

트랜스크립트는 크다 — 실측으로 한 파일이 **21.6MB** 였다. 그래서:
목록은 (크기·mtime·오프셋) 캐시로 **자란 부분만** 읽고(초회 186ms → 이후 3ms),
상세는 **꼬리 512KB** 만 읽는다(21.6MB 파일에 6ms).

## "이 폴더의 세션이 목록에 없다"

실제로 나온 물음이다 — Description 이 VS Code 에 열려 있고 거기서 작업도 했는데 목록에 없었다.

답: **열린 폴더와 세션은 다른 것이다.** 세션 목록은 `~/.claude/projects/<슬러그>/*.jsonl`,
즉 *그 폴더에서 시작된* 세션이다. Description 슬러그에는 `.jsonl` 이 **0개**였다 —
그 세션은 `EasyAI.Platform` 에서 시작해 Description 으로 옮겨가 일했을 뿐이다.
빠뜨린 것이 아니라 애초에 Description 에서 Claude Code 를 시작한 적이 없다.

그래서 화면은 **열린 폴더를 세션 목록 위에 나란히** 보여준다. `~/.claude/ide/<포트>.lock`
에서 VS Code 워크스페이스를 읽어 폴더별로 이렇게 적는다:

| 폴더 | 뜻 |
|------|-----|
| `● 세션 3` | 이 폴더에서 시작한 세션이 3개 |
| `⇄ 여기서 시작한 세션 없음 · 다른 곳에서 시작한 1개가 작업 중` | **Description 의 경우** |
| `○ 세션 없음` | 열려 있지만 여기서 Claude Code 를 시작한 적이 없다 |

- pid 로 **열린 창과 닫힌 창의 흔적을 구별**한다. 실측으로 9일 된 낡은 lock 이 남아 있었다.
- 🔴 lock 파일에는 `authToken` 이 들어 있다. **읽는 즉시 버리고 응답에 담지 않는다.**

### 그래도 안 보이면 — 프로세스를 직접 본다

CLI 가 모르는 것이 있을 수 있다. 실측으로 `claude agents --json` 이 세션 2개를 보고할 때
실제 `claude.exe` 는 **4개**였다(나머지 둘은 `--claude-in-chrome-mcp` 보조). CLI 만 믿었으면
그 둘의 존재조차 몰랐다. 그래서 **살아 있는 프로세스를 직접 열거**해 목록 끝에 붙인다:

```text
세션 행에 짝지어지지 않은 claude 프로세스  ? 2개
  ⚙ 보조 프로세스 (세션 아님)   pid 2284   시작 09-15 15:26  VS Code 확장 2.1.263
  ⚙ 보조 프로세스 (세션 아님)   pid 31668  시작 09-18 09:27  VS Code 확장 2.1.263
```

프로세스에서만 알 수 있는 것이 있고, 그중 둘은 중요하다:

- **어느 바이너리인가** — VS Code 는 npm 판이 아니라 **확장에 번들된**
  `.vscode\extensions\anthropic.claude-code-<버전>\resources\native-binary\claude.exe` 를 쓴다.
  버전도 다를 수 있다(실측: 확장 2.1.263 vs npm 2.1.246).
- **권한 우회 여부** — 실측으로 두 세션 모두 `--permission-mode bypassPermissions
  --allow-dangerously-skip-permissions` 로 돌고 있었다. 화면에 `▲ 권한 우회로 실행 중` 으로 뜬다.

`--add-dir` 로 붙은 폴더도 여기서 보인다. **'Description' 이 목록에 없던 이유가 이것이다** —
Description 은 두 세션 모두의 `--add-dir` 이지 독립 세션이 아니었다.

## 한 세션이 여러 곳을 오간다

실측: 세션 하나가 `EasyAI.Platform`(1443 엔트리) · `Description`(4378) · `Description/_plan/_resume`(23)
를 오갔다. 그래서 cwd 를 셋으로 나눠 담는다 — **실행cwd**(띄운 자리) · **주작업cwd**(가장 많이
머문 곳, 저장소·추적기 짝짓기는 이쪽) · **최근cwd**(중단 지점의 단서).
UI 는 여러 곳을 오간 세션에 `⇄ 여러 위치` 를 붙이고 분포를 보여준다.

🔴 재시작은 **추적기를 소유한 저장소(`repo`)에서** 띄운다 — 실행cwd 가 아니다. 다른 곳에서 띄우면
지시문이 가리키는 파일이 작업 폴더 밖이라 쓰기가 전부 승인 대기가 된다(실측 2026-09-28: 턴 22 ·
$18.27 · **디스크 변경 0건** · 권한거부 11건). 일해 온 폴더는 `--add-dir` 로 함께 넘어가고, 둘 다 로그에 남는다.

## 남은 한계

- **감시 기록은 추적하지 않는다**(`state/`). 백업 복원 상황에서는 없다 — 그때는 대상 저장소의
  추적기가 남긴 **단계 경계까지만** 복구된다.
- **재개 지점은 추적기나 재개지시에서 온다.** 그 둘이 없으면 재시작은 돌지 않는다.
  임의의 세션에 "알아서 계속하라"고 시키지 않는다.
- **`--max-turns` 가 이 CLI 버전(2.1.246)에 없다.** 폭주는 벽시계 타임아웃(기본 30분)으로만 막는다.
- **캐시 쓰기 5분 배수(×1.25)는 역산하지 못했다** — 표본에 5분 쓰기가 없었다. 공표 배수를 쓴다.

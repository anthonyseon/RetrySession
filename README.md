# RetrySession

Claude Code 세션을 **세션 바깥에서** 감시하고 재시작한다. 의존성 없음 — `node` 만 있으면 돈다.

## 이것이 푸는 문제

Claude Code 세션이 닫히면 그 안에서 돌던 것은 전부 멈춘다. 세션 안 예약(cron)도 함께 멈춘다.
그래서 "중단되면 이어서 하기"를 세션 안에 두면, 정작 중단됐을 때 아무도 깨워주지 못한다.

앞선 계획에서 실제로 겪은 일이다:

> **2026-09-16 23:02 ~ 09-17 08:04 (9시간)** `setInterval` 이 멈춰 기록이 끊겼다. 예약도 같은 구간에 발동 0건.
> 절전 아님(Kernel-Power 0건) · 재부팅 아님(가동 46.6h) · 프로세스 사망 아님(PID 28472 생존).
> **PC 는 깨어 있었고 프로세스도 살아 있었는데 타이머만 멈췄다.**

그때 대책으로 기록만 OS 작업 스케줄러로 옮겼지만, 비대칭이 남았다 —
**기록은 바깥에 있는데 재개는 여전히 세션 안이나 사람 손에 있었다.**
RetrySession 은 그 비대칭을 없앤다. 감시와 재시작 **둘 다** OS 에 둔다.

## 세 가지 트리거

| # | 무엇 | 어디서 도는가 | 주기 |
|---|------|--------------|------|
| ① | **감시** — 어디까지 왔는지 디스크에 기록 | OS 작업 스케줄러 `EasyAI-RetrySession-Heartbeat` | 5분 |
| ② | **재시작** — `claude --resume` 로 실제로 이어서 진행 | OS 작업 스케줄러 `EasyAI-RetrySession-Resume` | 15분 |
| ③ | **UI** — 실시간 상태 화면 | OS 작업 스케줄러 `EasyAI-RetrySession-UI` | 로그온 시 |

세 개 모두 **Claude Code 세션과 무관하게** 돈다. 세션을 닫아도, VS Code 를 닫아도 계속 돈다.

**장수 타이머를 쓰지 않는다.** 5분마다 OS 가 새 프로세스를 띄운다 — 얼어붙을 타이머 자체가 없다.
그래서 `heartbeat.mjs` 에는 `--loop` 이 없다. 다시 넣지 마라. 그게 9시간 중단의 원인이었다.

## 시작하기

```bash
npm test                                  # 83개 테스트 (판정 로직이 여기에 고정돼 있다)
npm run ui                                # http://127.0.0.1:7345
```

UI 에서 세션을 골라 감시·재시작을 켠 뒤, OS 에 등록한다:

```powershell
.\scripts\register-all.ps1                # 감시 + UI (아무것도 쓰지 않는다)
.\scripts\register-all.ps1 -WithResume    # 재시작까지 (토큰을 쓴다)
.\scripts\status.ps1                      # 등록 상태 + 기록 신선도
.\scripts\unregister-all.ps1              # 전부 해제 (state/ 는 남는다)
```

`register-all.ps1` 은 기본으로 **재시작을 등록하지 않는다.** 사람 없이 토큰을 쓰고 파일을 고치는
일이라 명령줄에 `-WithResume` 을 적는 명시적 동작이어야 한다.

## UI

`http://127.0.0.1:7345` — **로컬 전용이다.** 이 화면은 재시작을 띄울 수 있으므로 바인드 주소를 바꾸지 마라.

- **세션 목록** — 다중 선택해서 감시·재시작을 한꺼번에 켜고 끈다. 실행 중 여부(pid), 활동 시각, 턴·도구·토큰·정가
- **상세** — 선택한 세션의 처리 상황·대화·도구 호출을 2초마다 갱신. 감시 로그 · 재시작 로그 · 재개지시 설정
- **사용량** — 계정·구독, 모델별 토큰과 정가 환산, 사용량 제한 상태와 해제 시각
- **OS 트리거** — 세 작업의 등록 여부·마지막 결과·다음 실행

화면 오른쪽 위에 **"n초 전 갱신"** 이 항상 떠 있다. 화면이 멈추면 바로 알 수 있어야 한다.

## 인증과 비용

**VS Code 에 로그인된 Claude Code 계정을 그대로 쓴다.** API 키를 쓰지 않는다.
그래서 예약 작업은 **같은 Windows 사용자 · Interactive 로그온**으로 등록된다 —
`%USERPROFILE%\.claude` 의 자격증명을 읽어야 하기 때문이다. 실행 환경에서
`ANTHROPIC_API_KEY` 계열을 비워 계정 프로필이 항상 이기게 한다.

화면의 금액은 **정가 환산 참고값**이다. 구독(`max`)이면 실제 청구액이 아니다.
토큰 수는 트랜스크립트 실측이고, 환산은 실측 검증된 단가를 쓴다:

| | 단가 | 근거 |
|---|---|---|
| 입력 | $5.00 / 1M | 정가표 (claude-opus-5) |
| 출력 | $25.00 / 1M | 정가표 |
| 캐시 쓰기(1h) | 입력 × 2 | **실측 역산** |
| 캐시 읽기 | 입력 × 0.1 | **실측 역산** |

`claude -p --output-format json` 이 보고한 `total_cost_usd` 와 우리 계산이 **오차 0** 으로 맞는다
(표본 2건, `test/pricing.test.mjs` 에 고정). 단가는 `config/pricing.json` 에서 고친다.

> `claude -p` 1회는 아무 일도 안 해도 최소 **~$0.21** 든다 — 시스템 프롬프트 캐시 생성 21k 토큰이
> 매 프로세스마다 새로 잡힌다. 그래서 재시작에는 횟수 상한과 **비용 상한**이 함께 있다.

## 재시작이 실행되지 않는 조건

사람이 보고 있지 않은 실행이다. 가드를 **전부** 통과해야만 `claude --resume` 이 뜬다.

1. UI 에서 그 세션의 재시작이 켜져 있는가
2. 조용한 시간이 아닌가 (`조용한시간`, 기본 끔)
3. **세션 프로세스가 실행 중이 아닌가** — `claude agents --json` 의 pid 로 확인.
   사람이 쓰는 세션은 절대 건드리지 않는다. `--force` 로도 건너뛸 수 없다.
4. 최근 N분 활동이 없는가 (기본 10분)
5. **재개 지점이 있는가** — 추적기의 `doing`/`todo`, 또는 UI 에서 넣은 재개지시.
   둘 다 없으면 무엇을 이어서 할지 정해지지 않은 것이므로 돌지 않는다.
6. 예산 — 하루 횟수(12) · 하루 비용($5) · 최소 간격(30분) · 연속 실패 차단(3회)
7. 세션별 락 — 두 개가 같은 대화에 쓰지 않게

막힌 것은 이유를 로그에 적고 **exit 0** 으로 끝낸다. 스케줄러 이력이 실패로 더러워지지 않게.

재개 지시문에는 항상 이 두 줄이 들어간다:

- 판단이 갈리는 지점에서는 **멈춘다.** 추측으로 진행하지 않는다.
- 되돌리기 어려운 작업은 하지 않는다: force push · 브랜치 삭제 · 파일 대량 삭제 · 외부 전송

## 판정은 fail-closed 다

> **감시 장치가 "모르면 정상"이라고 답하면 감시가 아니다.**

실측 사고: 임시로 쓴 하트비트 판정이 `atEpoch` 가 없을 때 "살아있음"으로 답했고,
실제로는 9시간 낡은 상태였다. 그 fail-open 때문에 중단을 놓쳤다.

그래서 모든 판정은 "모르면 안 된다"로 답하고, `test/guard.test.mjs` 가 그것을 고정한다 —
파일이 없으면 죽음, 상태가 깨졌으면 예산 거부, 조용한시간 형식이 틀리면 조용한 시간,
세션 활성을 모르면 재시작 금지.

## 구조

```
config/
  projects.json          대상 저장소·기본값 (추적함 / 경로가 다르면 projects.local.json)
  pricing.json           단가표 (실측 검증 기록 포함)
src/
  heartbeat.mjs          ① 감시 본체        hb.mjs  ← 스케줄러가 부르는 ASCII 진입점
  resume.mjs             ② 재시작 본체      rs.mjs  ← 같은 이유
  ui/server.mjs          ③ 화면 (127.0.0.1) index.html · app.js
  lib/
    config.mjs  targets.mjs     설정 · 대상 등록부
    sessions.mjs detail.mjs     세션 목록·사용량(증분 캐시) · 상세 타임라인
    cli.mjs                     claude CLI 를 정보 출처로 (agents --json · auth status)
    tracker.mjs probe.mjs       추적기 판정 · git·세션 관측
    guard.mjs                   🔴 fail-closed 판정 (낡음·조용한시간·예산·락)
    pricing.mjs stamp.mjs       비용 환산 · 로컬 시각
    status.mjs scheduler.mjs    집계(화면·CLI 공용) · schtasks 조회
scripts/*.ps1            OS 등록·해제·상태 (🔴 전부 ASCII)
state/                   런타임 기록 (추적 안 함)
test/                    83개 — 판정·단가·ASCII 규칙을 고정
```

**왜 `hb.mjs` / `rs.mjs` 가 따로 있나** — PowerShell 5.1 은 `.ps1` 을 ANSI 로 읽어서 한글이
들어가면 파서가 죽는다(실측). 스케줄러가 건드리는 경로는 ASCII 여야 한다.
`test/ascii.test.mjs` 가 이 규칙을 기계로 지킨다 — 이 도구를 만드는 중에도 한 번 어겼기 때문이다.

## 정보를 어디서 읽는가

CLI 가 주는 것은 CLI 로 얻고, 없는 것만 파일에서 읽는다. CLI 는 공식 인터페이스고 파일은 내부 구조다.

| 출처 | 주는 것 |
|---|---|
| `claude agents --json` | 실행 중 세션 — pid · cwd · kind · startedAt · name |
| `claude auth status --json` | 계정 — email · orgName · subscriptionType · authMethod |
| `~/.claude/projects/*/*.jsonl` | 토큰 · 모델 · 제목 · 도구 호출 · 대화 · `quotaLimits` |
| `schtasks /Query` | OS 예약 등록 여부 · 마지막 결과 |

트랜스크립트는 크다 — 실측으로 한 파일이 **21.6MB** 였다. 그래서:
목록은 (크기·mtime·오프셋) 캐시로 **자란 부분만** 읽고(초회 186ms → 이후 3ms),
상세는 **꼬리 512KB** 만 읽는다(21.6MB 파일에 6ms).

## 한 세션이 여러 곳을 오간다

실측: 세션 하나가 `EasyAI.Platform`(1443 엔트리) · `Description`(4378) · `Description/_plan/_resume`(23)
를 오갔다. 그래서 cwd 를 하나로 담지 않고 셋으로 나눈다.

- **실행cwd** — 프로세스를 띄운 자리. 재시작을 여기서 띄운다.
- **주작업cwd** — 가장 많이 머문 곳. 저장소·추적기 짝짓기는 이쪽이다.
- **최근cwd** — 마지막으로 있던 곳. 중단 지점의 단서다.

UI 는 여러 곳을 오간 세션에 `⇄ 여러 위치` 를 붙이고 분포를 보여준다.

## 남은 한계

- **감시 기록은 추적하지 않는다**(`state/`). 백업 복원 상황에서는 없다 — 그때는 대상 저장소의
  추적기가 남긴 **단계 경계까지만** 복구된다.
- **재개 지점은 추적기나 재개지시에서 온다.** 그 둘이 없으면 재시작은 돌지 않는다.
  임의의 세션에 "알아서 계속하라"고 시키지 않는다.
- **`--max-turns` 가 이 CLI 버전(2.1.246)에 없다.** 폭주는 벽시계 타임아웃(기본 30분)으로만 막는다.
- **캐시 쓰기 5분 배수(×1.25)는 역산하지 못했다** — 표본에 5분 쓰기가 없었다. 공표 배수를 쓴다.
